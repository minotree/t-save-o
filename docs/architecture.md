# 초기 구조와 결정 (2026-10-28)

## 최신 변경: 실제 글리프 기반 ‘성’

첫 ‘성’은 [seong-font.md](seong-font.md)의 Noto Sans KR 원본 윤곽 분할 데이터를 사용한다. `puzzle.ts`는 `font-seong.ts`를 선택하고 기존 `instantiateTemplate`으로 네 조각을 연결한다. 엔진·공통 템플릿·Game UI는 수정하지 않았다. 아래 공통 렌더링 설명은 다른 자모에 그대로 적용되지만 ‘성’의 모양 입력은 실제 글리프 자산으로 대체됐다.

## 최신 변경: 공통 SVG Path 렌더링

현재 렌더링/충돌 기준은 [vector-rendering.md](vector-rendering.md)다. `jamo-templates.ts`의 공통 자음/모음 Path를 `puzzle.ts`에서 조합하고, `vector-shape.ts`의 곡선 분할·윤곽 삼각분해로 표시와 같은 도형의 두께를 충돌에 반영한다. 화살촉의 방향이 실제 이동 벡터의 원본이며 곡선도 모양을 유지한 채 병진 이동한다. 다음의 초기 선분 기반 설명·좌표는 변경 이력이며 현재 구현 기준을 대신하지 않는다.

## 후속 변경: 첫 플레이 가능한 퍼즐

최신 사용자 요청으로 설계 문답을 중단하고 첫 글자 ‘성’만 구현한다. 아래 초기 문서는 이력으로 보존하며 현재 충돌·기능 범위는 이 절과 AGENTS.md를 따른다.

- apps/web/src/game/engine.ts: 브라우저 독립 선분 경로 판정. 각 선분의 시작/퇴장 끝점을 잇는 볼록 껍질은 해당 선분의 연속 이동 영역이다. 이동이 선분과 평행하면 선분으로 퇴화한다. 연결 조각은 선분별 영역의 합으로 검사하며 꺾인 조각의 빈 공간 전체를 채우지 않는다.
- 상대 선분과 이동 영역의 교차/포함 또는 고정 원판과의 접촉을 검사한다. 화살촉·표시 두께·충돌 반경·정밀 외곽은 계산하지 않는다. EPS=1e-8은 이번 360×340 논리 좌표에서 사용하는 수치 비교값이며 디자인 간격이 아니다.
- 퇴장 벡터는 모든 점이 보드 한쪽 경계를 완전히 벗어나는 시점에 표시 여유 32를 더해 계산한다. 전체 선분 퇴장 경로를 먼저 판정한 후 600ms 표시 애니메이션, 650ms에 상태에서 제거한다. 퇴장 중 다른 선택은 잠깐 차단해 이동 중 충돌 상태를 만들지 않는다. 재시작 시 예약 제거 타이머를 취소한다.
- hangul-layout.ts는 200단위 음절 셀에서 세로 모음+받침 조합의 초성·중성·종성 영역을 정의한다. placeInSyllable은 셀 원점·자모 영역·자모 내부 좌표를 합쳐 실제 좌표를 만든다. puzzle.ts의 획 모양과 배치를 분리해 같은 조합의 다른 글자나 여러 셀에서 재사용할 수 있다. 일반 한글 자동 분해·모든 조합 템플릿은 아직 없다.
- 현재 ‘성’의 ㅅ은 왼쪽 (110,178)→(173,92), 오른쪽 (220,178)→(168,108)의 약 54도 직선이다. straightArrow는 각 획의 끝점 차이를 방향 벡터로 사용해 (63,-86), (-52,-70)으로 이동한다. 직선 획에 45도/8방향 제한을 적용하지 않는다. 왼쪽은 오른쪽과 만나지 않고, 오른쪽의 위쪽 연장 경로는 약 (164.6,103.4)에서 왼쪽 획에 막힌다. 동일 꼭짓점 접촉은 피하도록 중심선 간격을 남긴다. 받침 ㅇ은 (177,226), 반지름 34다. 정답 순서는 저장하지 않는다. 화살촉은 표시 전용이며 실제 방향을 따른다. ㅓ는 기존 끝점 10×10 marker를 사용하고, ㅅ은 꼭짓점 겹침을 피하려 획 길이의 60% 지점에 8.5×9 머리를 별도 표시한다. 어느 것도 충돌·선택 영역에는 포함하지 않는다.
- 모든 합법 제거 순서의 완료 가능성은 작은 첫 보드의 전수 분기 테스트로 확인한다. 자동 생성·의존 그래프 최적화·일반 한글 음절 분석은 이번 범위에 넣지 않는다.
- Game.tsx는 SVG 클릭·터치·Enter/Space, 오답 색상/안내, 퇴장·완료 연출·재시작을 담당한다. 본문 스크롤과 Safe Area를 유지하고 모션 감소 설정을 따른다.

현재 실행 단위는 apps/web 하나다. pnpm workspace에 apps/*와 packages/*를 등록했으며 실제 공통 로직이 생길 때만 packages를 추가한다. 토스와 모바일 앱은 각각 독립 UI와 빌드를 갖추고 도메인 규칙·계약·데이터 접근만 공유한다.

## 선택 근거

- 로컬 Node 24.22.0 / pnpm 10.34.7을 유지한다. [Vite 공식 요구사항](https://vite.dev/guide/)의 Node 20.19+ / 22.12+ 범위를 충족한다.
- 레지스트리 조회 기준 React/DOM 19.3.1, Vite 8.3.5, TypeScript 7.0.2, vite-plugin-pwa 2.0.0을 선택했다. PWA 플러그인의 peer 범위에 Vite 8이 포함된다. TypeScript는 Apache-2.0, 나머지 직접 런타임·빌드 패키지는 MIT다.
- 최소 구조에서는 Vite의 TSX 변환을 사용하고 Fast Refresh용 React 플러그인은 생략한다. React 변경은 페이지 새로고침으로 반영된다. 라우터·UI 라이브러리·광고 SDK는 아직 불필요하다.
- [Vite PWA](https://vite-pwa-org.netlify.app/guide/)의 generateSW와 prompt 갱신을 사용한다. 해시가 있는 앱 셸 정적 자산만 사전 캐시하고 오래된 precache는 정리한다. API runtime cache는 없다. 첫 온라인 방문 이전의 오프라인 실행은 지원하지 않는다.
- 아이콘은 이 저장소 초기화 작업에서 System.Drawing으로 원과 단색 배경을 직접 그린 임시 기하 아이콘이다. 외부 이미지·폰트를 사용하지 않았다. 정식 브랜드 자산은 미정이다.

## 서비스 경계

게임 진행·완료 이력은 기획대로 IndexedDB에 저장할 예정이며 아직 구현하지 않았다. Supabase는 검증된 원격 퍼즐 배포를 담당할 예정이고 계정 기반 동기화는 미확정이다. Cloudflare는 웹 정적 호스팅 우선 후보이며 운영 서비스·계정·도메인은 생성하지 않았다. 지도·Vercel은 현재 필요하지 않다.

## 범위와 충돌 처리

현재 사용자 요청은 PWA 우선 개발이다. 기존 PRD의 웹·토스 동시 첫 출시 및 토스 호환성 기준과 별개로 개발 순서에 적용한다. 기획 작업지시서의 ‘검토만’ 단계는 이번 최소 구조 생성 요청 범위에서 갱신된 것으로 해석한다. 게임 구현은 별도 단계다.

다음 후보는 공통 퍼즐 계약·충돌/풀이 검증 엔진과 테스트다. 전체 게임을 구현하기 전 세부 단계와 미확정 사항을 확인한다. 원본 인수인계서가 없으므로 PRD의 확정 규칙 1~44를 기준으로 하고 누락 원본을 발견하면 비교한다.
