# 공통 자모 SVG Path 렌더링 (2026-10-28)

후속 적용: 첫 ‘성’은 [실제 폰트 글리프 적용 기록](seong-font.md)의 Noto Sans KR 윤곽으로 교체했다. 이 문서의 직접 작성한 공통 템플릿·엔진·근사 오차는 그대로 유지하며, 아래 ‘성’의 초기 공통 템플릿 적용 설명은 이력이다.

이 문서의 기준은 기존 두께 없는 선분 설계를 대체한다. 변경 범위는 공통 자모 렌더링/충돌 구조와 현재 ‘성’에 대한 적용이며 홈·버튼·오답·완료·재시작 흐름과 다른 퍼즐 콘텐츠는 유지한다.

## 데이터와 재사용

- `jamo-templates.ts`: 현대 초성 자음 19개·모음 21개 및 겹받침의 정규화된 100×100 자모 템플릿. 겹자음/복합모음은 기본 템플릿을 조합한다. ㄹ 등은 꺾임을 Q로, ㅅ·ㅈ·ㅊ 등은 C로 표현한다. ㅇ과 ㅎ 원형은 움직이는 획에 합치지 않는다.
- 각 움직이는 조각은 SVG Path 명령, 두께, 화살촉 부착점과 방향을 갖는다. 템플릿 head.direction에서 실제 이동 벡터와 화면의 화살촉 각도를 함께 만든다. 45도/8방향 제한은 없다. 곡선은 휘어진 경로를 따라 이동하지 않고 모양 그대로 직선 병진 이동한다.
- 자모의 기준 부착점은 자체 Path 위로 투영하고 배치 후에도 실제 몸통 위에 있는지 검사한다. 렌더러에는 siot 등 특정 자모 ID에 따른 분기가 없다. 같은 원본 shape를 SVG 표시, 선택 Path, 충돌 계산에 사용한다.
- `hangul-layout.ts`: 음절 셀과 초성·중성·종성 영역. `instantiateJamo`는 영역 크기에 맞춰 모든 제어점·부착점·방향 벡터를 변환한다. 출력 두께는 명시적 논리 단위(현재 6.2)이며 화면 픽셀이나 해상도와 무관하다. ㅇ의 radius는 테두리 두께까지 포함한 외곽 충돌 반지름이다.
- 난이도 조각 수는 자모 전체 2/3/4개 상한이다. 고정 원형은 제외한다. 상한 초과는 명시 오류로 반환하고 임의 조각 삭제·추가 연결은 하지 않는다. ㄿ처럼 현재 템플릿이 5조각인 겹받침은 최대 4개 범위에서 제외된다. 각 이동 조각의 연결성도 검사한다.
- 이 템플릿 목록은 모든 자모의 재사용 가능한 형상 데이터다. 모든 조합이 곧바로 풀이 가능한 퍼즐이라는 뜻은 아니다. 첫 ‘성’만 초기 비겹침과 모든 합법 제거 순서를 승인 테스트로 검증했다. 향후 자모·조합별 가독성/간격/방향 검수와 퍼즐 승인을 거친다.

## 글꼴 윤곽 검토와 도입

[OpenType.js의 glyph Path API](https://github.com/opentypejs/opentype.js/blob/master/src/glyph.mjs)와 [공식 저장소](https://github.com/opentypejs/opentype.js)를 검토했다. 글리프 전체 윤곽을 얻는 것과 게임에서 제거할 개별 획을 분리하는 것은 별도 작업이다. 겹치거나 연결된 글리프 윤곽에서 어떤 부분을 한 조각으로 이동할지 자동 결정하지 않는다.

현재 기본 템플릿은 이 작업에서 직접 작성한 SVG 획이며 외부 폰트 윤곽을 복사하지 않았다. 특정 글꼴과 픽셀 단위로 일치한다고 보장하지 않는다. 외부 폰트 파일·폰트 파서의 런타임 의존성은 추가하지 않았다.

검토된 폰트 윤곽은 `instantiateTemplate`으로 같은 엔진에 넣을 수 있다. 각 조각에 절대 좌표 M/L/Q/C/Z 명령을 제공하고 `fill: true`, `strokeWidth: 0`을 설정하면 닫힌 윤곽의 실제 폭을 사용한다. 내부 구멍은 even-odd 규칙을 따른다. 상대 명령·H/V/A는 사전에 M/L/Q/C로 변환해야 하며 미지원 입력은 오류로 반환한다. 서로 교차하지 않는 검토된 단순 윤곽을 사용한다. 획 분리·화살촉 위치/방향과 글꼴의 사용 권한은 도입 단계에서 확인해야 한다.

## 충돌 형상과 근사 오차

`vector-shape.ts`는 SVG와 동일한 명령으로 충돌 기본 형상을 만든다. [Bézier subdivision 원리](https://pomax.github.io/bezierinfo/#splitting)를 참고한 De Casteljau 분할을 사용했다.

- Q/C 곡선을 각 구간 제어점과 유한 chord 사이 거리가 0.025 논리 단위 이하가 될 때까지 분할한다. 한 선분으로 되돌아오는 곡선과 끝점 너머 돌출도 검사한다. 분할 한도를 넘으면 조용히 승인하지 않고 오류를 반환한다.
- 열린 획은 분할 선분과 `두께/2` 반지름의 캡슐 합집합이다. SVG stroke-linecap/linejoin=round와 대응한다. 곡선에는 누락을 막기 위해 최대 근사 오차만큼 보수적인 반경을 더한다. 직선에는 이 추가량이 없다.
- 채워진 윤곽은 earcut으로 구멍을 보존한 삼각형들로 분해한다. 둥근 획과 같은 연속 이동 검사에 넣는다. 전체 글자의 AABB나 볼록 껍질로 대체하지 않으므로 꺾임 내부/글꼴의 빈 공간을 함부로 막지 않는다.
- 각 캡슐/삼각형을 실제 방향으로 완전 퇴장까지 이동한 영역을 구성하고 상대 도형과의 거리를 반지름 합과 비교한다. 한 번이라도 접촉하면 이동 거리는 0이다. 고정 ㅇ은 내부 전체의 원판 장애물이다. 화살촉은 이전처럼 표시 전용이다.
- 따라서 곡선 충돌은 해석적 무한 정밀 계산이 아니라 0.025 단위 오차를 관리하는 보수적 근사다. 양쪽 곡선의 극소 간격은 보수적으로 차단될 수 있다. 픽셀·프레임 간격·화면 배율에 의존하지 않는다.
- shape의 분할/삼각분해는 WeakMap에 캐시한다. 편집 시 shape와 commands를 새 객체로 만들어 캐시를 갱신한다.

## ‘성’과 검증 범위

`puzzle.ts`는 ㅅ·ㅓ·ㅇ 템플릿과 기존 조합 영역만 선택한다. 글자 전용 좌표 목록이나 정답 순서 표를 갖지 않는다. 곡선과 두께를 반영하니 기존 방향에서 왼쪽 획도 막혀, 공통 ㅅ 템플릿의 왼쪽 head.direction을 (40,-78)로 지정했다. 배치된 방향은 (44,-67.08), 오른쪽은 (-34.1,-49.88)이며 표시 화살촉과 동일하다. 어느 획도 회전·변형하지 않는다.

Vitest는 73개 검사로 기존 제거 관계·전체 합법 분기, 40개 현대 자모의 Path·연결성·화살촉·상한, ㅎ 고정 원형, 두께 접촉/간격, 곡선 돌출, 닫힌 윤곽/구멍, 가져온 윤곽의 공통 처리, 강체 평행 이동을 확인한다. Playwright는 데스크톱/모바일 에뮬레이션 4개 검사로 막힘 경고·제거·성공·재시작 및 이동 중 Path 불변을 확인한다. 실제 모바일 기기와 다른 글자의 퍼즐 승인은 별도다.

런타임 추가 의존성은 `earcut@3.2.4`(ISC) 하나이며 자체 타입을 사용한다. 배포물에 `third-party-notices.txt`를 함께 포함한다. 본 작업 기준 메인 JS gzip은 약 80 kB이며 전체 앱·템플릿을 포함한 값이다.
