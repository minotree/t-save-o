# 두 가지 퍼즐 생성 방식

2026-10-30 사용자가 제시한 두 화면의 생성 방식을 따로 보존하고, 앞으로 두 방식으로 게임 콘텐츠를 구성하기로 했다. 이 명칭과 내부 키는 문서상 구분이며 사용자용 메뉴 명칭의 확정은 아니다.

| 구분 | A형 · 격자 충전형 (`grid-fill`) | B형 · 글리프 필획형 (`glyph-stroke`) |
| --- | --- | --- |
| 기준 화면 | 검정 경로가 공간을 채운 12×12 ‘성’ | 초록 글자로 배치한 ‘우리가 / 저마다 / 힘에겨운’ |
| 출발점 | 격자의 모든 유효 점과 ㅇ 예외 영역 | 실제 Noto Sans KR Regular 글리프 윤곽 |
| 구성 | 사선·직선·여러 번 꺾인 경로로 모든 유효 점을 한 번씩 사용하고, 독립 화살표들로 분할 | 원본 윤곽을 연결된 필획으로 분할하고, 실제 글자/문장으로 배치 |
| 여백 | ㅇ 내부/접촉 점 이외의 격자점 누락 금지 | 글자 내부와 글자 사이 원래 여백 허용. 격자 전체 채움 조건 없음 |
| 한글 표현 | 직접 작성한 경로로 한글 형태를 표현. 실제 폰트 글리프라는 주장을 하지 않음 | 원본 곡선·글자 비율·가독성을 보존. 독립 자모 변형이나 가짜 연결선을 추가하지 않음 |
| 사선 | 실제 격자점을 지나는 사선. 계단 대체/45도 한정 금지 | 원본 획의 자연스러운 기울기와 명시적 출구 벡터 유지 |
| 현재 예시 | 144점=사용128+ㅇ예외16, 25화살표·친구1명 | 37필획·친구4명, 3줄/한 줄 최대4글자 |
| 실행 데이터 | `grid-review.generated.json` → `grid-review.ts` | `phrase-puzzle.ts` → `createPhrasePuzzle('four-per-line-playable')` |
| 저작/생성 | `generate-grid-review.py`로 오프라인 작성/탐색 후 정적 결과 저장 | 사전 추출·분할·검토한 글리프/필획과 고정 레이아웃 사용 |
| 실행 중 자동 생성 | 없음 | 없음. 임의 문장의 범용 자동 글리프 분해기도 미구현 |
| 고유 검증 | 모든 점 소유권·ㅇ 예외·누락/중복0·셀 내부 경로 교차 금지 | 원본 글리프와 분할 몸통의 비교·연결성·분할 상한·곡선/구멍 보존 |

## 공통 원칙

- 실제 표시 본체와 충돌 본체를 같은 shape 데이터로 구성한다. 화살촉의 표시 방식과 판정용 원점은 구분한다.
- 꼬리부터 원래 경로를 비우며 출구 방향으로 나간다. 자기 몸통을 향하지 않는 출구를 설계하고, 실제 기하에서 다른 획/ㅇ의 막힘 관계를 얻는다. 정답 순서를 하드코딩하지 않는다.
- 모든 합법적 제거 순서의 풀이 가능성과 중복 처리 방지, 실제 클릭·터치·키보드, 움직임 중 잠금, 취소·재시작 시 타이머/RAF 정리를 검증한다.
- 글리프·폰트 원본과 라이선스는 B형에서 보존한다. A형의 직접 작성한 경로와 실제 폰트 윤곽을 혼동하지 않는다.

## 병행 범위와 미확정 사항

두 방식을 게임 콘텐츠에 함께 사용한다. A형이 최신이라는 이유로 B형을 폐기하지 않으며, B형을 A형의 전 격자 충족 규칙으로 억지 변형하지 않는다.

현재 예시에서 A형은 외부 화살촉/글자 소유 획 제거 후 개별 구출, B형은 내부 색동 끝단/전체 제거 후 구출을 사용한다. 이 차이를 이번 기록으로 임의 통일하지 않는다. 공통화 여부는 후속 설계에서 결정한다.

메뉴·코스·난이도별 배치, 혼합 문제 도입, 노출 비율·문제 수는 미확정이다. 초급12×12·중급20×20·고급30×30도 사용자 예시이며 확정된 규격이 아니다. 이번 기록은 새 선택 UI·전체 코스 교체·실행 중 자동 생성의 구현을 의미하지 않는다.
